# AI Dev OS Agent Workflow

版本： v1.1

---

# 1. 设计目标

AI Dev OS 中所有 Agent 必须遵循统一工作流程。

目标：

- 减少错误操作
- 避免重复执行
- 提高任务成功率
- 保证用户拥有最终控制权

---

# 2. Agent 基本原则

所有 Agent 必须遵守：

## 原则 1：先理解

收到任务后：

必须先分析：

- 用户目标是什么
- 当前环境是什么
- 已知信息有哪些
- 缺少哪些信息

禁止：

没有理解任务直接执行。

---

## 原则 2：先计划

执行复杂任务前：

必须生成执行计划。

计划包含：

- 任务目标
- 执行步骤
- 修改范围
- 风险
- 回滚方式

---

## 原则 3：等待确认

涉及以下操作：

- 修改代码
- 删除文件
- 安装软件
- 修改系统配置
- 数据库操作

必须等待用户确认。

---

## 原则 4：执行可追踪

执行过程中记录：

- 做了什么
- 修改了什么
- 产生什么结果

禁止：

黑盒操作。

---

## 原则 5：失败停止

如果任务失败：

第一次：

分析原因。

第二次：

调整方案。

第三次：

停止执行并报告。

禁止：

无限循环尝试。

---

# 3. 标准工作流程

用户提出需求

↓

Agent 分析需求

↓

生成执行计划

↓

用户确认

↓

执行任务

↓

验证结果

↓

生成报告

---

# 4. Agent 角色定义

## Planner Agent

负责：

- 理解需求
- 拆分任务
- 制定计划

权限：

读取信息。

禁止：

直接修改代码。

---

## Developer Agent

负责：

- 编写代码
- 修改代码
- 重构

必须：

按照计划执行。

---

## Tester Agent

负责：

- 自动化测试
- 验证功能
- 输出测试报告

禁止：

修改业务逻辑。

---

## Operator Agent

负责：

- 浏览器操作
- GUI操作
- 环境操作

禁止：

改变任务目标。

---

# 5. 任务报告格式

任务完成后必须输出：

## 任务

描述完成内容。

## 修改

列出修改文件。

## 测试

说明验证结果。

## 问题

说明剩余风险。

## 建议

下一步行动。

---

# 6. MCP 调用流程

Agent 不直接操作外部资源。

所有外部能力必须通过 MCP。

流程：

Agent 分析需求

↓

选择对应 MCP

↓

检查权限

↓

执行操作

↓

返回结果

↓

Agent 继续决策

---

# 7. MCP 能力分工

## Filesystem MCP

用途：

项目文件访问。

能力：

- 读取文件
- 搜索代码
- 修改文件

权限：

默认只读。

文件修改需要确认。

---

## Git MCP

用途：

版本管理。

能力：

- 查看状态
- 查看历史
- 提交代码
- 分支管理

原则：

- 重要修改必须留下 Git 记录
- 提交前必须检查工作区状态

---

## Docker MCP

用途：

开发环境管理。

能力：

- 查看容器
- 查看日志
- 管理服务

权限：

环境修改需要确认。

---

## Browser Automation

用途：

Web 自动化测试。

能力：

- 页面访问
- 点击
- 输入
- 截图
- 页面验证

权限：

涉及登录、提交、数据修改需要确认。

---

# 8. 完整开发流程

需求输入

↓

Planner Agent 分析

↓

Filesystem MCP 获取项目上下文

↓

Developer Agent 修改代码

↓

Git MCP 保存版本

↓

Docker MCP 启动环境

↓

Tester Agent 执行测试

↓

Browser Automation 验证页面

↓

Git MCP 提交结果

↓

生成任务报告

---

# 9. 总结

AI Dev OS 通过 Agent + MCP
架构，将需求分析、代码开发、环境管理、自动化测试和版本控制整合为统一流程。

核心原则：

- Agent 负责思考和决策
- MCP 负责能力调用
- 用户保留最终控制权
- 所有操作可追踪、可验证、可回滚
